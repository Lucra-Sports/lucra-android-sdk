# Tournament API
The Pool Tournament feature allows end users to join pre-created tournaments and earn rewards based on their ranking at the end of the matchup.

The outcome and payout structure of each pool must be provided to Lucra using these API endpoints

## Headless `Tournament` payload

`retrieveTournamentDetails` returns `RetrieveTournamentDetailsResult.TournamentDetailsOutput` with a single tournament's details.

`retrieveTournamentLeaderboard` returns `RetrieveTournamentLeaderboardResult.TournamentLeaderboardOutput` with one page of that tournament's leaderboard and the signed-in user's own entry.

`queryRecommendedTournaments` returns `RecommendedTournamentsOutput`. This overload returns the full `Tournament` payload and is deprecated for recommended tournament lists.

`queryRecommendedTournaments(locationId = ...)` returns `QueryRecommendedTournamentsLightResult.RecommendedTournamentsOutput`.

### `Participant`

Each item in `tournament.participants` is a `Tournament.Participant` with:

* **`id`** — Lucra user id (string).
* **`username`** — Display name.
* **`place`** — Leaderboard place from the API, when present.
* **`placeOverride`** — Optional place override for that leaderboard row.
* **`rewardValue`** — Payout / reward value for this row when applicable.
* **`score`** — Leaderboard score string for the participant. `null` when there is no leaderboard data for that participant or no score yet.
* **`avatarUrl`** — Profile avatar URL when the user has one, or `null` otherwise.

### Tournament reward structure

`Tournament.rewardType` and `Tournament.payoutStructure` were populated only by the removed `retrieveTournament` call. On the `Tournament` payloads that remain, from `submitUserScore` and the full `queryRecommendedTournaments` overloads, both are `null`. Read a tournament's payout structure from [`LucraTournamentDetails.payoutStructure`](#tournament-details) instead. The cash `rewardStructure` list is unchanged.

### Tournament details

`retrieveTournamentDetails` reads Lucra's `GET /user/tournaments/:id` endpoint and returns `com.lucrasports.tournament.LucraTournamentDetails`, which mirrors that response field for field: nothing is derived or filled in on the device. Enumerated values are the raw strings Lucra sends, so handle values you don't recognise, and timestamps are ISO 8601 strings. Free-form objects (`CatalogReward.config`, `userMetadata`) are `Map<String, Any?>`. The same types, with the same names, are in the iOS SDK. The leaderboard is a separate call, [`retrieveTournamentLeaderboard`](#tournament-leaderboard).

The call works signed in or signed out. When the user is signed in, the request carries their session.

| Property | Type | Description |
|---|---|---|
| `id` | `String` | Tournament id. |
| `title` / `description` | `String` / `String?` | Display copy. |
| `status` | `String` | `"ACTIVE"`, `"COMPLETED"` or `"CANCELED"`. |
| `matchupStatus` | `String` | The raw lifecycle status that `status` summarises, such as `"OPEN"`, `"LOCKED"` or `"CLOSED"`. |
| `type` | `String` | Short reward type: `"CASH_FIXED"`, `"CASH_PERCENTAGE"`, `"TENANT_REWARD"` or `"NO_REWARD"`. |
| `matchupRewardType` | `String?` | Long reward type, such as `"POOL_TOURNAMENT_CASH_FIXED_REWARD"` or `"POOL_TENANT_REWARD"`. |
| `visibility` | `String` | `"PUBLIC"`, `"PRIVATE_VIEWABLE"` or `"PRIVATE_HIDDEN"`. |
| `isPrivate` | `Boolean` | `true` for both private visibilities. |
| `gameId` | `String?` | The game the tournament is played on. |
| `imageUrl` | `String?` | The tournament's own image, when it has one. |
| `displayImageUrl` | `String?` | The image to show: the tournament's image, else its game's background, else its game's icon. |
| `buyIn` | `String` | Buy-in as a two-decimal string, such as `"5.00"`. |
| `buyInAmount` | `Double` | Buy-in in dollars. |
| `freeBuyIn` | `Boolean` | `true` when the buy-in is zero. |
| `feePercent` | `String` | Fee as a two-decimal string. |
| `poolNetAmount` | `Double` | Pool net of fees, in dollars. `0` when there is no reward structure. |
| `poolNetAmountComplete` | `Double` | Net pool in dollars if the tournament fills. |
| `maxParticipants` | `Int?` | Participant cap; `null` when uncapped. |
| `participantsCount` | `Int` | Current entrant count. |
| `maxAttempts` | `Int?` | Attempts allowed per user. |
| `startsAt` / `expiresAt` | `String?` | When the tournament begins and when it stops accepting entries. Scores can still be submitted after `expiresAt`, so read `isCompleted` to decide whether a tournament is over. |
| `signUpStart` / `signUpEnd` / `createdAt` | `String?` | Sign-up window and creation time. |
| `isCompleted` / `isNotStarted` / `isExpired` | `Boolean` | Lifecycle flags. Some canceled tournaments report `isCompleted = false` even though `status` is `"CANCELED"`. |
| `isJoinable` | `Boolean` | Whether someone who has not joined could join now. It does not reflect the current user. |
| `timer` | `Timer` | `state` (`"before_signup"`, `"signup_open"`, `"before"`, `"ongoing"` or `"ended"`), an English `caption` such as `"Ends in 2 hours"`, and `targetAt`, the time the caption counts to. The caption can be a minute stale; render a live countdown from `targetAt`. |
| `howToPlay` | `List<HowToPlayStep>?` | Ordered steps (`step`, `text`); `null` when the tournament and its game define none. |
| `terms` | `List<Term>` | Terms the user confirms before joining (`title`, `description`). |
| `payoutStructure` | `PayoutStructure` | See below. |
| `leaderboardColumns` | `List<LeaderboardColumn>` | The columns to render for the leaderboard (`name`, `label`). The payout column is present only while payouts are visible. |
| `notices` | `List<Notice>` | Explanations for hidden or altered values: `type` (such as `"PAYOUT_HIDDEN_BELOW_THRESHOLD"`), `message`, and `affectedFields`, the paths of the fields it explains. |
| `game` | `Game?` | `gameId`, `minigameEnabled`, `scoringUnit`, `imageBgUrl`, `iconUrl`; `null` when there is no game. When `minigameEnabled` is `true`, joining uses the minigame geo compliance contexts. |

The nested types are `LucraTournamentDetails.Timer`, `.HowToPlayStep`, `.Term`, `.PayoutStructure`, `.PayoutReward`, `.CatalogReward`, `.LeaderboardColumn`, `.Notice` and `.Game`.

`PayoutStructure` has `title`, `description`, `labelTitle`, `labelDescription`, `noPayout`, `isPercentagePayout`, `showAmount`, `jackpotDescriptor`, `jackpotAmount` and `rewards`. Each `PayoutReward` has `place` and `endPlace` (equal for a single position), `placeLabel`, `positionLabel`, `value`, `rewardLabel`, `amountLabel` and `catalogReward`.

`CatalogReward` has `id`, `type`, `title`, `descriptor`, `iconUrl`, `bannerIconUrl`, `disclaimer` and `config`, the reward's tenant-authored configuration as a `Map<String, Any?>` (empty when there is none).

### Tournament leaderboard

`retrieveTournamentLeaderboard` reads Lucra's `GET /user/tournaments/:id/leaderboard` endpoint and, when the user is signed in, `GET /user/tournaments/:id/leaderboard/me` for their own entry. Both are mirrored field for field.

`TournamentLeaderboardOutput.leaderboard` is a `com.lucrasports.tournament.LucraTournamentLeaderboard` with:

* **`entries`** — the page's `LucraTournamentLeaderboard.Entry` rows.
* **`totalCount`** — the total number of rows, or `null` if Lucra did not report one.
* **`currentUserEntry`** — the signed-in user's `LucraTournamentLeaderboard.CurrentUserEntry`, or `null` when they are signed out or have no entry.

If either read fails, the whole call fails.

Each `Entry` contains:

| Property | Type | Description |
|---|---|---|
| `userId` | `String` | Lucra user id. |
| `userName` / `userAvatarUrl` | `String?` | Username and avatar. |
| `userMetadata` | `Map<String, Any?>?` | The user's tenant metadata, or `null` when there is none. |
| `name` | `String` | Display name; the current user's row is suffixed ` (You)`. |
| `rank` | `Int?` | Rank to display; `null` until the user has a score. |
| `position` / `positionOverride` | `Int` / `Int?` | Raw leaderboard position and any override. |
| `score` / `points` | `Double?` / `String?` | Raw score and its display string. |
| `payout` | `String?` | Formatted reward, such as `"$21.50"`; `null` when payouts are hidden, the row has no score, or the reward is zero. |
| `isCurrentUser` | `Boolean` | `true` on the signed-in user's own row; always `false` signed out. |
| `rewardTotalAmount` / `rewardNetAmount` / `rewardFeeAmount` / `rewardNetAmountComplete` | `Double` | Raw reward amounts in dollars. |
| `numberOfParticipants` | `Int` | Entrant count. |
| `bestAttempt` / `openAttempt` / `lastAttempt` | `Int?` | Attempt numbers for the row's best score, open attempt and latest attempt. |
| `canSubmitNewScore` | `Boolean` | Whether the row's user has an open attempt. |
| `lastUpdatedAt` | `String?` | When the leaderboard was last recomputed. |

`CurrentUserEntry` has `userId`, `userName`, `userMetadata`, `userAvatarUrl`, `position`, `positionOverride`, `score` and `lastUpdatedAt`, as on an entry.

### Migrating from the earlier `retrieveTournamentDetails`

The earlier `TournamentDetails` (`com.lucrasports.sdk.core.contest.tournament.TournamentDetails`) was a single combined payload. It is replaced by `com.lucrasports.tournament.LucraTournamentDetails` plus `retrieveTournamentLeaderboard`:

| Earlier | Now |
|---|---|
| `retrieveTournamentDetails(tournamentId, leaderboardLimit, leaderboardOffset)` | `retrieveTournamentDetails(tournamentId)` and `retrieveTournamentLeaderboard(tournamentId, limit, offset)` |
| `leaderboard.rows`, `leaderboard.pagination.totalCount` | `TournamentLeaderboardOutput.leaderboard.entries`, `.totalCount` |
| `leaderboard.columns` | `LucraTournamentDetails.leaderboardColumns` |
| `userLeaderboardRow` | `leaderboard.currentUserEntry`, or the entry whose `isCurrentUser` is `true` |
| `visibilityLevel` | `visibility` |
| `totalParticipants` | `participantsCount` |
| `rewardType` | `matchupRewardType` |
| `minigameEnabled` | `game?.minigameEnabled` |
| `timer.state` (`"NOT_STARTED"`, `"STARTED"`, `"ENDED"`) | `timer.state` (`"before_signup"`, `"signup_open"`, `"before"`, `"ongoing"`, `"ended"`) |
| `startsAt` / `expiresAt` as `Date?` | ISO 8601 `String?` |
| `payoutStructure` as `PayoutStructure?` | `LucraTournamentDetails.PayoutStructure`, always present |
| `howToPlay` as an empty list | `null` when there are no steps |
| `attemptData`, `earnedRewards` | Not available from these calls |

### Lightweight recommended tournaments

The location-aware `queryRecommendedTournaments` overload returns a smaller tournament payload for headless integrations. It includes tournament details, game details, payout structure, the top five leaderboard rows, and the current user's leaderboard row when present.

This lightweight payload intentionally does not include full participant groups, all participants, or the full leaderboard. Use `isUserPresent`, `canJoinTournament`, `totalParticipants`, and `leaderboard` instead of deriving those values from `Tournament.participants`.

Each `RecommendedTournamentLight` contains:

* **`id`** — Tournament matchup id.
* **`title`** — Tournament title.
* **`type`** — Tournament detail type.
* **`status`** — Tournament status string.
* **`iconUrl`** — Tournament icon URL.
* **`fee`** — Tournament fee.
* **`buyInAmount`** — Tournament buy-in amount.
* **`potTotal` / `potNetAmount`** — Tournament pot totals matching the full tournament payload.
* **`description`** — Tournament description.
* **`metadata`** — Tournament metadata string when present.
* **`createdAt` / `updatedAt` / `startsAt` / `expiresAt`** — Tournament timestamps.
* **`creatorId` / `creator`** — Tournament creator identity when present.
* **`maxParticipants` / `totalParticipants`** — Participant limits and current count.
* **`visibilityLevel` / `rewardType` / `subtype` / `matchupType`** — Matchup classification fields.
* **`maxAttempts`** — Max attempts allowed for this tournament.
* **`minPayoutAmount`** — Minimum payout amount when present.
* **`canJoinTournament`** — Whether the current user can join, when returned by the API.
* **`isUserPresent`** — Whether the current user is present in the tournament.
* **`game`** — Game data with id, name, description, icon/image URLs, categories, win criteria, track-results copy, scoring unit, and `minigameEnabled` flag.
* **`rewardStructure`** — Payout structure rows.
* **`terms`** — Tournament terms when present.
* **`leaderboard`** — Up to five leaderboard rows plus the current user's row when present.

Each `RecommendedTournamentGameLight` contains:

* **`id`** — Game id.
* **`name`** — Game name.
* **`description`** — Game description.
* **`iconUrl` / `imageUrl` / `imageBgUrl`** — Game imagery.
* **`categoryIds`** — Game category names.
* **`howToWin`** — Human-readable win condition.
* **`winCriteria`** — Win criteria copy and instructions when present.
* **`trackResults`** — Track-results label and description when present.
* **`scoringUnit`** — Score unit label when present.
* **`minigameEnabled`** — Whether the game has minigames enabled. When `true`, tournament join flows use minigame-specific geo compliance contexts (`FreeMinigames` / `CashMinigames`).

Each `RecommendedTournamentRewardStructureLight` contains:

* **`position`** — Reward position.
* **`value`** — Reward value.
* **`tierNetAmount` / `tierFeeAmount` / `tierTotalAmount`** — Reward tier amounts.

Each `RecommendedTournamentLeaderboardRowLight` contains:

* **`participantGroupId`** — Leaderboard participant group id, when present.
* **`userId`** — Lucra user id.
* **`username`** — Display name.
* **`place`** — Leaderboard place from the API, when present.
* **`placeOverride`** — Optional place override for that leaderboard row.
* **`score`** — Leaderboard score string.
* **`avatarUrl`** — Profile avatar URL when the user has one, or `null` otherwise.

**Methods**

`retrieveTournamentDetails`

Retrieve the details for a tournament with a given ID. See [Tournament details](#tournament-details).

* **Parameters:**
  * `tournamentId`: ID associated with the tournament.
  * `onResult`: Callback with a result of type `RetrieveTournamentDetailsResult`.
* **Example usage:**

```kotlin
LucraClient().retrieveTournamentDetails(tournamentId = "tournamentId") { result ->
    when (result) {
        is RetrieveTournamentDetailsResult.Failure -> {
            // Handle failure scenario
        }
        is RetrieveTournamentDetailsResult.TournamentDetailsOutput -> {
            val details = result.details
            println("${details.title} (${details.status}, ${details.timer.caption})")

            val payout = details.payoutStructure
            if (!payout.noPayout) {
                println("Payout: ${payout.title} (${payout.jackpotAmount.orEmpty()})")
                payout.rewards.forEach { reward ->
                    println("${reward.positionLabel} – ${reward.amountLabel.orEmpty()}")
                }
            }
        }
    }
}
```

`retrieveTournamentLeaderboard`

Retrieve one page of a tournament's leaderboard, plus the signed-in user's own entry. See [Tournament leaderboard](#tournament-leaderboard).

* **Parameters:**
  * `tournamentId`: ID associated with the tournament.
  * `limit`: Page size. Defaults to `10`; Lucra accepts up to `100`.
  * `offset`: Number of rows to skip. Defaults to `0`.
  * `onResult`: Callback with a result of type `RetrieveTournamentLeaderboardResult`.
* **Example usage:**

```kotlin
LucraClient().retrieveTournamentLeaderboard(
    tournamentId = "tournamentId",
    limit = 25,
    offset = 0,
) { result ->
    when (result) {
        is RetrieveTournamentLeaderboardResult.Failure -> {
            // Handle failure scenario
        }
        is RetrieveTournamentLeaderboardResult.TournamentLeaderboardOutput -> {
            val leaderboard = result.leaderboard
            leaderboard.entries.forEach { entry ->
                println("${entry.rank ?: "-"}. ${entry.name} – ${entry.payout.orEmpty()}")
            }
            println("Rows in total: ${leaderboard.totalCount}")
            leaderboard.currentUserEntry?.let { println("You are at position ${it.positionOverride ?: it.position}") }
        }
    }
}
```

### **Generic Errors:**

All the Failure responses above are subtypes of `FailedTournamentCall`. This serves as a general way to parse errors coming from the tournament headless calls.

**User State Errors (account-related issues)**

* `NotInitialized` - User session not properly set up or account data missing
* `Unverified` - User hasn't completed identity verification (KYC) for real-money tournaments
* `NotAllowed` - User account restricted, suspended, or ineligible
* `InsufficientFunds` - Not enough balance for paid tournament entry
* `DemographicInformationMissing` - Missing email/zip code for free tournaments

**Location Errors**

* `LocationError` - Geographic restrictions (banned states, location services disabled, GeoComply failures)

**API Errors**

* `APIError` - Network issues, server errors, invalid responses, rate limits



`FailedTournamentCall`

These errors occur during tournament operations (retrieve, join, query, submit score) and help determine the appropriate user-facing message and recovery action.

```kotlin
sealed interface FailedTournamentCall {
    sealed interface UserStateError : FailedTournamentCall {
        data object NotInitialized : UserStateError
        data object Unverified : UserStateError
        data object NotAllowed : UserStateError
        data object InsufficientFunds : UserStateError
        data object DemographicInformationMissing : FailedTournamentCall
    }
    data class LocationError(val message: String) : FailedTournamentCall
    data class APIError(val message: String) : FailedTournamentCall
}
```

2. **New error handling** - add handling for `DemographicInformationMissing` error

**Before:**

```kotlin
LucraClient().joinTournament(tournamentId) { result ->
    when (result) {

        is JoinTournamentResult.Failure -> {
```

**After:**

```kotlin
LucraClient().joinTournament(tournamentId) { result ->
    when (result) {

        is JoinTournamentResult.Failure -> {
```

### Troubleshooting

#### Common Issues

* Demographic form not launching for free tournaments.
  * Ensure user authentication is complete before attempting to join tournaments
* Form not auto-filling previously entered data
  * The form should auto-fill based on saved user data. If not working, check user authentication state
* `DemographicInformationMissing` error not being handled.
  * &#x20;Add the new error case to your tournament joining error handling

# Tournament API
The Pool Tournament feature allows end users to join pre-created tournaments and earn rewards based on their ranking at the end of the matchup.

The outcome and payout structure of each pool must be provided to Lucra using these API endpoints

## Headless `Tournament` payload

`retrieveTournamentDetails` returns `RetrieveTournamentDetailsResult.TournamentDetailsOutput`. This is the recommended call for single-tournament lookups.

`retrieveTournament` returns `RetrieveTournamentResult.RetrieveTournamentOutput`. This call returns the full `Tournament` payload and is deprecated in favor of `retrieveTournamentDetails`.

`queryRecommendedTournaments` returns `RecommendedTournamentsOutput`. This overload returns the full `Tournament` payload and is deprecated for recommended tournament lists.

`queryRecommendedTournaments(locationId = ...)` returns `QueryRecommendedTournamentsLightResult.RecommendedTournamentsOutput`.

### `Participant`

Each item in `tournament.participants` is a `Tournament.Participant` with:

* **`id`** — Lucra user id (string).
* **`username`** — Display name.
* **`place`** — Leaderboard place from the API, when present.
* **`placeOverride`** — Optional place override for that leaderboard row.
* **`rewardValue`** — Payout / reward value for this row when applicable.
* **`score`** — Leaderboard score string for the participant. `null` when there is no leaderboard data for that participant or no score yet.
* **`avatarUrl`** — Profile avatar URL when the user has one, or `null` otherwise.

### Tournament reward structure

`retrieveTournament` returns the full reward structure on `Tournament`, mirroring what Lucra's own in-app tournament details screens render. This is an additive change — the existing cash `rewardStructure` list is retained unchanged.

| Property | Type | Description |
|---|---|---|
| `rewardType` | `String?` | Raw API reward category. `"POOL_CASH_REWARD"` for cash tournaments, `"POOL_TENANT_REWARD"` for tangible-prize tournaments. Use this to determine which presentation branch to render. `null` when the backend does not supply one. |
| `payoutStructure` | `PayoutStructure?` | Full payout structure as returned by the backend. `null` when the backend does not supply one. |
| `rewardStructure` | `List<RewardStructure>` | **Retained.** Cash payout list (position + amounts). Unchanged from previous versions. |

`Tournament.PayoutStructure`:

| Property | Type | Description |
|---|---|---|
| `title` | `String` | Section heading for the payout block (e.g. `"Payouts"`). |
| `description` | `String` | Supporting copy beneath the title. |
| `labelTitle` | `String?` | Optional column header for the place column. |
| `labelDescription` | `String?` | Optional column header for the reward column. |
| `noPayout` | `Boolean` | `true` when this tournament has no monetary or tangible payout. |
| `isPercentagePayout` | `Boolean` | `true` when rewards are expressed as pool percentages rather than fixed amounts. |
| `showAmount` | `Boolean` | Whether to display the `amountLabel` values in your UI. |
| `jackpotAmount` | `String?` | Pre-formatted total prize pool label (e.g. `"$1,000"`). |
| `jackpotDescriptor` | `String?` | Label accompanying the jackpot amount (e.g. `"Total Payout"`). |
| `rewards` | `List<PayoutReward>` | Ordered list of per-position reward rows. |

`Tournament.PayoutReward`:

| Property | Type | Description |
|---|---|---|
| `place` | `Int?` | Starting position this row applies to. |
| `endPlace` | `Int?` | Ending position for tie ranges; equals `place` for a single position. |
| `placeLabel` | `String?` | Pre-formatted place label (e.g. `"1st"`, `"4th–10th"`). |
| `positionLabel` | `String?` | Pre-formatted position label (e.g. `"1st Place"`). |
| `rewardLabel` | `String?` | Pre-formatted reward descriptor (e.g. `"40%"`, `"Grand Prize"`). |
| `amountLabel` | `String?` | Pre-formatted payout amount (e.g. `"$1,000"`). |
| `value` | `Double?` | Raw numeric reward value. |
| `catalogReward` | `CatalogReward?` | Tangible reward details. `null` for cash-only rows. |

`Tournament.CatalogReward`:

| Property | Type | Description |
|---|---|---|
| `id` | `String` | Unique catalog reward identifier. |
| `type` | `String` | Reward category (e.g. `"COUPON"`, `"FREE_ITEM"`). |
| `title` | `String` | Display name of the reward. |
| `description` | `String?` | Short description of the reward. |
| `iconUrl` | `String?` | URL of the reward icon image. |
| `bannerIconUrl` | `String?` | URL of the reward banner image. |
| `disclaimer` | `String?` | Legal or fine-print text associated with the reward. |

> `CatalogReward` intentionally omits redemption details (discount codes, claim URLs, free-item IDs). Use `getUserTournamentRewards` to access a claimed reward's full redemption payload.

### Lightweight tournament details

`retrieveTournamentDetails` is backed by the `ui_tournament_details` API — the same response that powers Lucra's own in-app tournament details screen — and returns a `TournamentDetails` payload sized for headless integrations.

Compared to the deprecated `retrieveTournament` full `Tournament` payload, `TournamentDetails` intentionally does not include full participant lists, pot totals, fees, tournament metadata, or rich game info. Use `leaderboard`, `userLeaderboardRow`, `totalParticipants`, and `attemptData` instead of deriving those values from `Tournament.participants`.

Each `TournamentDetails` contains:

* **`id`** — Tournament matchup id.
* **`title` / `description` / `imageUrl`** — Tournament display copy and banner image.
* **`isPrivate` / `visibilityLevel`** — Visibility classification (`"PUBLIC"`, `"PRIVATE_VIEWABLE"`, `"PRIVATE_HIDDEN"`).
* **`isCompleted` / `isNotStarted` / `isExpired`** — Lifecycle state flags.
* **`status`** — Tournament status string.
* **`freeBuyIn` / `buyInAmount`** — Buy-in details. Treat the tournament as free when `freeBuyIn` is `true` or `buyInAmount` is `0`/`null`.
* **`maxParticipants` / `totalParticipants`** — Participant limits and current count.
* **`rewardType`** — Raw API reward category (e.g. `"POOL_CASH_REWARD"`, `"POOL_TENANT_REWARD"`), or `null` when the backend does not supply one.
* **`gameId` / `minigameEnabled`** — Game identity and minigame flag.
* **`howToPlay`** — Ordered how-to-play steps (`step`, `text`).
* **`earnedRewards`** — Rewards the current user has earned in this tournament (`id`, `place`, `reward` as `CatalogReward`).
* **`timer`** — Countdown caption and state (`"NOT_STARTED"`, `"STARTED"`, `"ENDED"`) when present.
* **`attemptData`** — Replay/attempt info for the current user: `canJoinTournament`, `isReplayable`, `isUserPresent`, `presentToUser`, `attemptsRemaining`, `rankVariation`, recommendation copy, `iconType`, and per-attempt `scores` (`attempt`, `score`, `isBest`).
* **`payoutStructure`** — Same `PayoutStructure` payload documented above, or `null`.
* **`leaderboard`** — Column definitions, rows (`userId`, `name`, `payout`, `points`, `rank`), and pagination (`totalCount`, `offset`, `limit`). Page it with the `leaderboardLimit` / `leaderboardOffset` parameters.
* **`userLeaderboardRow`** — The current user's leaderboard row when present.
* **`terms`** — Tournament confirmation terms (`title`, `description`).

### Lightweight recommended tournaments

The location-aware `queryRecommendedTournaments` overload returns a smaller tournament payload for headless integrations. It includes tournament details, game details, payout structure, the top five leaderboard rows, and the current user's leaderboard row when present.

This lightweight payload intentionally does not include full participant groups, all participants, or the full leaderboard. Use `isUserPresent`, `canJoinTournament`, `totalParticipants`, and `leaderboard` instead of deriving those values from `Tournament.participants`.

Each `RecommendedTournamentLight` contains:

* **`id`** — Tournament matchup id.
* **`title`** — Tournament title.
* **`type`** — Tournament detail type.
* **`status`** — Tournament status string.
* **`iconUrl`** — Tournament icon URL.
* **`fee`** — Tournament fee.
* **`buyInAmount`** — Tournament buy-in amount.
* **`potTotal` / `potNetAmount`** — Tournament pot totals matching the full tournament payload.
* **`description`** — Tournament description.
* **`metadata`** — Tournament metadata string when present.
* **`createdAt` / `updatedAt` / `startsAt` / `expiresAt`** — Tournament timestamps.
* **`creatorId` / `creator`** — Tournament creator identity when present.
* **`maxParticipants` / `totalParticipants`** — Participant limits and current count.
* **`visibilityLevel` / `rewardType` / `subtype` / `matchupType`** — Matchup classification fields.
* **`maxAttempts`** — Max attempts allowed for this tournament.
* **`minPayoutAmount`** — Minimum payout amount when present.
* **`canJoinTournament`** — Whether the current user can join, when returned by the API.
* **`isUserPresent`** — Whether the current user is present in the tournament.
* **`game`** — Game data with id, name, description, icon/image URLs, categories, win criteria, track-results copy, scoring unit, and `minigameEnabled` flag.
* **`rewardStructure`** — Payout structure rows.
* **`terms`** — Tournament terms when present.
* **`leaderboard`** — Up to five leaderboard rows plus the current user's row when present.

Each `RecommendedTournamentGameLight` contains:

* **`id`** — Game id.
* **`name`** — Game name.
* **`description`** — Game description.
* **`iconUrl` / `imageUrl` / `imageBgUrl`** — Game imagery.
* **`categoryIds`** — Game category names.
* **`howToWin`** — Human-readable win condition.
* **`winCriteria`** — Win criteria copy and instructions when present.
* **`trackResults`** — Track-results label and description when present.
* **`scoringUnit`** — Score unit label when present.
* **`minigameEnabled`** — Whether the game has minigames enabled. When `true`, tournament join flows use minigame-specific geo compliance contexts (`FreeMinigames` / `CashMinigames`).

Each `RecommendedTournamentRewardStructureLight` contains:

* **`position`** — Reward position.
* **`value`** — Reward value.
* **`tierNetAmount` / `tierFeeAmount` / `tierTotalAmount`** — Reward tier amounts.

Each `RecommendedTournamentLeaderboardRowLight` contains:

* **`participantGroupId`** — Leaderboard participant group id, when present.
* **`userId`** — Lucra user id.
* **`username`** — Display name.
* **`place`** — Leaderboard place from the API, when present.
* **`placeOverride`** — Optional place override for that leaderboard row.
* **`score`** — Leaderboard score string.
* **`avatarUrl`** — Profile avatar URL when the user has one, or `null` otherwise.

**Methods**

`retrieveTournamentDetails`

Retrieve the lightweight details for a tournament with a given ID.

* **Parameters:**
  * `tournamentId`: ID associated with the tournament.
  * `leaderboardLimit`: Optional page size for the leaderboard section. Defaults to the server page size when `null`.
  * `leaderboardOffset`: Optional page offset for the leaderboard section.
  * `onResult`: Callback with a result of type `RetrieveTournamentDetailsResult`.
* **Example usage:**

```kotlin
LucraClient().retrieveTournamentDetails(tournamentId = "tournamentId") { result ->
    when (result) {
        is RetrieveTournamentDetailsResult.Failure -> {
            // Handle failure scenario
        }
        is RetrieveTournamentDetailsResult.TournamentDetailsOutput -> {
            val details = result.details
            println("${details.title} (${details.status})")

            // High-level reward category, e.g. "POOL_CASH_REWARD" / "POOL_TENANT_REWARD"
            details.rewardType?.let { println("Reward type: $it") }

            // Full payout structure with pre-formatted labels
            details.payoutStructure?.let { payout ->
                println("Payout: ${payout.title} (${payout.jackpotAmount.orEmpty()})")
            }

            // Leaderboard rows for the requested page
            details.leaderboard?.rows?.forEach { row ->
                println("${row.rank}. ${row.name} – ${row.payout}")
            }
        }
    }
}
```

* **Parameters:**
  * `tournamentId`: ID associated with the tournament.

`getUserTournamentRewards`

> **Experimental feature**: This method is marked `deprecated` to surface a compiler warning at every call site. This does not mean the method is going away; it signals that the feature is experimental. Use with caution and contact [Lucra support](mailto:support@lucrasports.com) if you need assistance.

Retrieve the current user's earned tournament rewards.

* **Parameters:**
  * `tournamentId`: Optional matchup/tournament id to scope results. Pass `null` to include all.
  * `viewed`: Filter by viewed status. Pass `null` to include both viewed and unviewed.
  * `claimed`: Filter by claimed status. Pass `null` to include both claimed and unclaimed.
  * `onResult`: Callback with a result of type `RewardInteractions.GetUserTournamentRewardsResult`.
* **Example usage:**

```kotlin
LucraClient().getUserTournamentRewards(
    tournamentId = "tournament_123",
    viewed = null,
    claimed = false,
) { result ->
    when (result) {
        is RewardInteractions.GetUserTournamentRewardsResult.Success -> {
            val rewards = result.rewards
            // Handle unclaimed rewards.
        }
        is RewardInteractions.GetUserTournamentRewardsResult.Failure -> {
            when (val error = result.failure) {
                is RewardInteractions.FailedRewardCall.User -> {
                    // NotInitialized or NotAllowed
                }
                is RewardInteractions.FailedRewardCall.CustomError -> {
                    Log.w("Lucra SDK", error.message)
                }
                RewardInteractions.FailedRewardCall.Unknown -> {
                    Log.w("Lucra SDK", "Unknown reward error")
                }
            }
        }
    }
}
```

**Errors:**

| Case | Description |
|---|---|
| `FailedRewardCall.User(NotInitialized)` | SDK is not initialized or no user is logged in. |
| `FailedRewardCall.User(NotAllowed)` | Account is blocked, suspended, or otherwise restricted. |
| `FailedRewardCall.CustomError(message)` | Backend returned a specific error message. |
| `FailedRewardCall.Unknown` | Unexpected error without a specific message. |

### **Generic Errors:**

All the Failure responses above are subtypes of `FailedTournamentCall`. This serves as a general way to parse errors coming from the tournament headless calls.

**User State Errors (account-related issues)**

* `NotInitialized` - User session not properly set up or account data missing
* `Unverified` - User hasn't completed identity verification (KYC) for real-money tournaments
* `NotAllowed` - User account restricted, suspended, or ineligible
* `InsufficientFunds` - Not enough balance for paid tournament entry
* `DemographicInformationMissing` - Missing email/zip code for free tournaments

**Location Errors**

* `LocationError` - Geographic restrictions (banned states, location services disabled, GeoComply failures)

**API Errors**

* `APIError` - Network issues, server errors, invalid responses, rate limits



`FailedTournamentCall`

These errors occur during tournament operations (retrieve, join, query, submit score) and help determine the appropriate user-facing message and recovery action.

```kotlin
sealed interface FailedTournamentCall {
    sealed interface UserStateError : FailedTournamentCall {
        data object NotInitialized : UserStateError
        data object Unverified : UserStateError
        data object NotAllowed : UserStateError
        data object InsufficientFunds : UserStateError
        data object DemographicInformationMissing : FailedTournamentCall
    }
    data class LocationError(val message: String) : FailedTournamentCall
    data class APIError(val message: String) : FailedTournamentCall
}
```

### Migration Guide

#### For Existing Integrators

If you're updating from an older SDK version:

1. **Additive change** - existing tournament joining code continues to work
2. **New error handling** - add handling for `DemographicInformationMissing` error

#### Example Migration

**Before:**

```kotlin
LucraClient().joinTournament(tournamentId) { result ->
    when (result) {
        is JoinTournamentResult.Success -> { /* handle success */ }
        is JoinTournamentResult.Failure -> {
            // Only handled KYC errors before
            if (result.failure is FailedTournamentCall.UserStateError.Unverified) {
                launchFlow(LucraUiProvider.LucraFlow.VerifyIdentity)
            }
        }
    }
}
```

**After:**

```kotlin
LucraClient().joinTournament(tournamentId) { result ->
    when (result) {
        is JoinTournamentResult.Success -> { /* handle success */ }
        is JoinTournamentResult.Failure -> {
            when (result.failure) {
                is FailedTournamentCall.UserStateError.Unverified -> {
                    launchFlow(LucraUiProvider.LucraFlow.VerifyIdentity)
                }
                is FailedTournamentCall.DemographicInformationMissing -> {
                    launchFlow(LucraUiProvider.LucraFlow.DemographicForm)
                }
            }
        }
    }
}
```

### Troubleshooting

#### Common Issues

* Demographic form not launching for free tournaments.
  * Ensure user authentication is complete before attempting to join tournaments
* Form not auto-filling previously entered data
  * The form should auto-fill based on saved user data. If not working, check user authentication state
* `DemographicInformationMissing` error not being handled.
  * &#x20;Add the new error case to your tournament joining error handling

# LucraClient Theming/Appearance

**Requires `:sdk-ui`***

Your can customize your Lucra implementation with your own color scheme and fonts by providing
the `ClientTheme` object to `LucraClient`.

`ClientTheme` takes a `lightColorStyle`, a `darkColorStyle`, a `FontFamily`, and a `themeMode`.

### ColorStyle

Represents the 6 different colors your can provide to the SDK. Each field in this class is an
hexadecimal string value.

The colors used
are `Primary`, `Secondary`, `Tertiary`, `OnPrimary`, `OnSecondary`, `OnTertiary`.

The SDK owns the neutrals. Values supplied for `background`, `surface`, `onBackground`, and
`onSurface` are ignored — including when those fields are set on a `ColorStyle` you pass in.

### Font Family

Represents a collection of the 4 different font styles that the SDK uses(`mediumFont`, `normalFont`, `semiBoldFont`, `boldFont`).
The name of the font style field corresponds with the font weight associated with the imported font file.
Each text style is represented by a `Font` object.

### Font

Each `Font` object requires you to specify the `fontAssetFilePath`.

The `fontAssetFilePath` is the exact file path of your custom font(ex: `/fonts/wingding.ttf`). The root directory is your assets
directory (`main/assets/`). All font files must be included in `assets`.
These fonts are imported through Reach Native.

```kotlin

LucraClient.initialize(
  /*...*/
  clientTheme = ClientTheme(
    lightColorStyle = ColorStyle(
      primary = "#1976D2",
      secondary = "#F57C00",
      tertiary = "#388E3C",
      onPrimary = "#FFFFFF",
      onSecondary = "#FFFFFF",
      onTertiary = "#FFFFFF",
    ),
    darkColorStyle = ColorStyle(
      primary = "#09E35F",
      secondary = "#5E5BD0",
      tertiary = "#9C99FC",
      onPrimary = "#001448",
      onSecondary = "#FFFFFF",
      onTertiary = "#FFFFFF",
    ),
    fontFamily = FontFamily(
      mediumFont = Font("my_medium_font.ttf"),
      normalFont = Font("my_regular_font.ttf"),
      semiBoldFont = Font("my_semi_bold_font.ttf"),
      boldFont = Font("my_bold_font.ttf"),
    ),
    themeMode = ThemeMode.AUTO,
  )
)
```

#### Note
Only specific sections of the UI will leverage the custom font passed into the LucraClient. These are for display purposes to fit the branding of the client app.

### Theme mode

`themeMode` decides whether the SDK renders light, dark, or follows the device. Force a mode when the
rest of your app is strictly light or strictly dark.

| `themeMode` | Appearance |
| --- | --- |
| `ThemeMode.LIGHT` | Always light, whatever the device is set to |
| `ThemeMode.DARK` | Always dark, whatever the device is set to |
| `ThemeMode.AUTO` | Follows the device's light/dark setting |
| Not set | Derived from which color styles you supplied — see below |

```kotlin
LucraClient.initialize(
  /*...*/
  clientTheme = ClientTheme(
    lightColorStyle = ColorStyle(/*...*/),
    darkColorStyle = ColorStyle(/*...*/),
    themeMode = ThemeMode.LIGHT,
  )
)
```

`themeMode` is read once, when `LucraClient.initialize` first runs. Later `initialize` calls reuse the
existing client and ignore the theme entirely — call `LucraClient.release()` first if you need to
change it.

If the mode you force has no matching `ColorStyle` — `ThemeMode.LIGHT` with only a `darkColorStyle`,
say — the SDK reuses the palette you did supply so your brand colors still apply, and logs a warning.
Those colors were chosen for the other appearance and may not meet contrast against it, so supply the
matching `ColorStyle` whenever you force a mode.

#### When `themeMode` is not set

Which styles you supply decides whether the SDK follows the system appearance or pins itself to one
mode. This is the pre-`themeMode` behavior, kept so existing integrations are unaffected:

| Supplied | Appearance |
| --- | --- |
| `lightColorStyle` and `darkColorStyle` | Follows the system appearance |
| `lightColorStyle` only | Locked to light |
| `darkColorStyle` only, or the deprecated `ClientTheme(colorStyle, fontFamily)` constructor | Locked to dark |
| Neither | Locked to dark, Lucra defaults |

Supply both only if your brand colors are legible in both. A palette that works in dark mode will
often fail contrast against light backgrounds — pick per-mode values, and check text colors against
the lighter surfaces before shipping. Partner values for `background`, `surface`, `onBackground`,
and `onSurface` do not affect rendering.

### Appearance changes

`ThemeMode.LIGHT` and `ThemeMode.DARK` ignore the device appearance, so a `uiMode` configuration
change cannot alter what the SDK renders.

With `ThemeMode.AUTO` — or with no `themeMode` and both `lightColorStyle` and `darkColorStyle`
supplied — your host Activity must declare `android:configChanges="uiMode"` for the palette to update
in place when the device switches between light and dark appearance. Without it, Android recreates
your Activity and rebuilds the hosted Lucra flow. See
[Host Activity Requirements](1.0.0_project_setup.md#appearance-lightdark-configuration-changes).

# Lucra Flows Setup and Usage

Lucra Flows are responsible for displaying specific user "flows" within the Lucra experience. This can be done one of 3 ways...
* Obtaining a `LucraFragment` and inflating it within your preferred experience.
* Generating `LucraDialogFragment` via `LucraClient().getLucraDialogFragment(lucraFlow)` for a full screen experience.
* Retrieving a `Composable` via `LucraClient().GetLucraFlowComposable(lucraFlow)` and adding it to you existing `Composable` layout.

Most flows can be navigated to from other Flows, e.g. the `Profile` flow is a common launch point. The other Flows are offered to launch specific experiences based on your use case.

After launching any given Flow, the nuance of what and how resulting Flows show up (within the user journey) is controlled by the `LucraUi#LucraFlowListener`, [see more details in the initialization guide](1.2.0_initialize_client)

**Requires `:sdk-ui`**

## Example Usage

### Fragment inflation (Embedded)

Embedding a `LucraFragment` directly into a `ViewGroup` in your layout gives you full control over where Lucra content appears within your app. This is useful when you want Lucra to live alongside your own native UI — for example, as a persistent tab in a bottom-navigation layout, as a section within a scrollable screen, or any context where a full-screen takeover is not appropriate for the initial entry point.

```kotlin
val lucraFlow = LucraUiProvider.LucraFlow.Profile
supportFragmentManager.beginTransaction()
  .add(
    R.id.lucraFragment,
    LucraClient().getLucraFragment(lucraFlow),
    lucraFlow.toString()
  )
  .commit()
```

#### Handling nested flows with `LucraFlowListener`

When a user interacts with an embedded `LucraFragment`, certain actions — such as identity verification, adding funds, or viewing a detailed profile — are designated as new flow entry points by the SDK. By default, these nested flows remain contained within the bounds of the embedded fragment's viewport.

For most integrations, you will want these nested flows to break out and appear full-screen. The `LucraFlowListener` — configured at initialization time via `LucraUi` — is the contract that enables this. It has two responsibilities:

- **`launchNewLucraFlowEntryPoint`**: called by the SDK when a new flow entry point needs to be displayed. Return `true` to take ownership of showing it (e.g. as a `LucraDialogFragment`). Return `false` to let the SDK display it within the existing fragment's viewport.
- **`onFlowDismissRequested`**: called by the SDK when a flow that your app launched should be dismissed. If you returned `true` for a given flow, you are responsible for dismissing it here.

The flow is identified by its tag — use `entryLucraFlow.toString()` consistently when showing and finding fragments so that `onFlowDismissRequested` can locate and dismiss the correct one.

```kotlin
LucraClient.initialize(
    ...
    lucraUiProvider = LucraUi(
        lucraFlowListener = object : LucraFlowListener {

            override fun launchNewLucraFlowEntryPoint(
                entryLucraFlow: LucraUiProvider.LucraFlow
            ): Boolean {
                LucraClient().getLucraDialogFragment(entryLucraFlow)
                    .show(supportFragmentManager, entryLucraFlow.toString())
                return true
            }

            override fun onFlowDismissRequested(
                entryLucraFlow: LucraUiProvider.LucraFlow
            ) {
                supportFragmentManager.findFragmentByTag(entryLucraFlow.toString())?.let {
                    if (it is DialogFragment) it.dismiss()
                    else supportFragmentManager.beginTransaction().remove(it).commit()
                }
            }
        }
    ),
    ...
)
```

> **Note:** The `LucraFlowListener` is set once at initialization and applies globally to all flows launched from this `LucraClient` instance. If you are launching a `LucraDialogFragment` instead (already full-screen), returning `false` from `launchNewLucraFlowEntryPoint` is typically correct — nested flows will remain within the dialog's own viewport without additional intervention.

### Fullscreen Dialog Fragment

```kotlin
// Or use the LucraDialogFragment to show the flow in a dialog
val lucraDialog = LucraClient().getLucraDialogFragment(lucraFlow)
lucraDialog.show(supportFragmentManager, lucraFlow.toString())
```

### Composable

```kotlin
Column (
    modifier = Modifier.fillMaxWidth(),
) {
    LucraClient().GetLucraFlowComposable(lucraFlow)
}
```

### Close all open Lucra Flows Fragments

We offer a simple way to close all open Lucra Flows programmatically. This only works if the Flow is launched using our `LucraClient().getLucraDialogFragment(lucraFlow)`

```kotlin
val dialog = LucraClient().getLucraDialogFragment(lucraFlow)
// ... later on, instead of calling `dialog.dismiss()` simply call the following

// NOTE: Only works if the Flow was launched using `LucraClient().getLucraDialogFragment(lucraFlow)`
LucraClient.closeFullScreenLucraFlows()
```

## Supported Lucra Flows

[Games You Play Specific Flows](2.1_gyp_flows.md)

[Tournaments Specific Flows](3.1_tournaments_flows.md)

`LucraUiProvider.LucraFlow.Login`
Launch to view the login flow

`LucraUiProvider.LucraFlow.VerifyIdentity`
Launch the verify identity flow for users. Allowing users to add and withdrawal money, as well as create and join real money matchups. This Flow will be launched automatically when other Flows require Verification before moving forward

`LucraUiProvider.LucraFlow.DemographicForm`
Launch the demographic form to collect user demographic information. This flow is required for free buy in tournaments and matchups.

`LucraUiProvider.LucraFlow.Profile`
Launch the profile view for users to add and withdrawal funds, identity verification will launch if
the user hasn't verified their identity yet

`LucraUiProvider.LucraFlow.Wallet`
Launch the wallet view to see balance, add/withdraw funds, and perform basic profile actions

`LucraUiProvider.LucraFlow.MyMatchup`
Launch to view the current user's matchups

`LucraUiProvider.LucraFlow.AddFunds`
Launch the add funds flow for users, identity verification will launch if the user hasn't verified
their identity yet

`LucraUiProvider.LucraFlow.WithdrawFunds`
Launch the withdraw funds flow for users, identity verification will launch if the user hasn't verified
their identity yet

`LucraUiProvider.LucraFlow.CreateSportsMatchup`
Launch the Create Sport Matchup flow to create a new sports matchup

`LucraUiProvider.LucraFlow.CreateGamesMatchup`
Launch the Create Games Landing page. Can support unauthenticated access. See [Games You Play Specific Flows](2.1_gyp_flows.md) for details.

`LucraUiProvider.LucraFlow.HomePage`
Launch the home page where user can create tournaments or matchups. Can support unauthenticated access. Takes optional location ID to initialize with specific location.

`LucraUiProvider.LucraFlow.PublicFeed`
Launch to view the public feed of sports matchups.

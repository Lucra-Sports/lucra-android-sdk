# Mini Games Headless Functions

The Lucra SDK exposes headless helpers so hosts can pre-warm geo compliance, launch minigame sessions, list the tenant's minigame catalog, observe the matchup service fee, and handle minigame matchup rewards without using the bundled UI. All functions live on `LucraClient` and report back through sealed result types, handle each branch to cover both success and failure paths.

[Headless function setup](1.2.9_headless_interactions.md)

## Preload a geo-compliance token
### `preloadGeoToken(type)`

Pre-fetch a GeoComply token for the given game context so the next `startMiniGame` call doesn't have to block on geo verification. Call this early, for example, when the buy-in sheet opens or when the user lands on the game lobby, so the token is cached before the user commits to playing. Fire-and-forget: there is no result callback, and failures are silently ignored. If no cached token is available when `startMiniGame` is invoked, the SDK will simply fetch one on demand.

- **Parameters**
  - `type`: (optional, default `LucraGeoTokenType.CashMinigame`) the game context to pre-fetch for.
- **Usage**

```kotlin
LucraClient().preloadGeoToken() // defaults to CashMinigame
// or, for a free entry minigame:
LucraClient().preloadGeoToken(type = LucraGeoTokenType.FreeMinigame)
```

### `LucraGeoTokenType`

| Value | Use for |
| --- | --- |
| `CashMinigame` | Paid minigame sessions (default). |
| `FreeMinigame` | Free / practice minigame sessions. |
| `CashBuyIn` | Paid recreational (GYP) matchups for non-minigame game types. |
| `FreeBuyIn` | Free recreational matchups for non-minigame game types. |

## Start a minigame session
### `startMiniGame(gameId, gameMode, amount, matchupId, onProgress, onResult)`

Launch a minigame session and obtain the URL the host should load in its own WebView. The SDK orchestrates user validation, funds checks (for cash modes), GeoComply verification, and the backend session call before invoking `onResult`. Surface `onProgress` updates to the user if you want a granular loading experience.

- **Parameters**
  - `gameId`: identifier of the game (e.g. `"runaway-web"`, `"hoops-web"`).
  - `gameMode`: a [`LucraMiniGameMode`](#lucraminigamemode) value.
  - `amount`: (optional) wager amount in USD. Pass `null` or `0.0` for practice / free entry.
  - `matchupId`: (optional) required for `LucraMiniGameMode.Tournament` (the tournament/matchup ID to join). Ignored for other modes.
  - `onProgress`: (optional) callback emitting [`MiniGameLaunchStep`](#miniGameLaunchStep) updates as the SDK works through launch.
  - `onResult`: callback receiving a `MiniGameInteractions.StartMiniGameResult`.
- **Results**
  - `StartMiniGameResult.Success` supplies `session: MiniGameSession` containing the iframe URL, the `sessionId`, and the associated `matchupId` (when applicable).
  - `StartMiniGameResult.Failure` wraps a `LucraError`. See the [Failure subtypes](#startminigame-failure-subtypes) table below.

### `LucraMiniGameMode`

| Value | `amount` | `matchupId` |
| --- | --- | --- |
| `Practice` | `null` / `0.0` | not required |
| `OneVsOne` | wager amount | not required |
| `FreeForAll` | wager amount | not required |
| `Tournament` | wager amount | **required** — the tournament/matchup ID to join |

### `MiniGameLaunchStep`

The SDK emits the following progress steps in order during a `startMiniGame` call:

| Step | When it fires |
| --- | --- |
| `ValidatingUser` | Before user state, KYC, and demographic checks. |
| `FetchingGeoToken` | Before the GeoComply token is fetched / refreshed. |
| `CallingAPI` | Just before the backend session call. |

### Response Model — `MiniGameSession`

| Property | Type | Description |
| --- | --- | --- |
| `iframeUrl` | `String` | URL to load in the host-owned WebView. |
| `sessionId` | `String` | Unique minigame session identifier. |
| `matchupId` | `String?` | Associated matchup ID (populated for non-practice sessions). |

### `startMiniGame` Failure subtypes

`StartMiniGameResult.Failure.failure` is one of:

| Subtype | Meaning |
| --- | --- |
| `UserStateError.NotInitialized` | SDK user is not initialized yet. Call after the user logs in. |
| `UserStateError.NotAllowed` | User is not allowed to play (e.g. blocked region or account state). |
| `UserStateError.Unverified` | User needs to complete identity verification before a cash session. |
| `UserStateError.InsufficientFunds` | User does not have enough balance for the requested wager. |
| `UserStateError.DemographicInformationMissing` | Tenant requires demographic data the user hasn't provided. |
| `LocationError` | GeoComply verification failed; `message` contains a human-readable cause. |
| `APIError` | Backend or unexpected failure; `message` contains the cause. |

- **Usage (practice mode)**

```kotlin
LucraClient().startMiniGame(
    gameId = "runaway-web",
    gameMode = LucraMiniGameMode.Practice,
    onProgress = { step ->
        Log.d("Lucra SDK", "Launch step: ${step.displayText}")
    },
) { result ->
    when (result) {
        is MiniGameInteractions.StartMiniGameResult.Success -> {
            val session = result.session
            // Load session.iframeUrl in your own WebView
            myWebView.loadUrl(session.iframeUrl)
        }
        is MiniGameInteractions.StartMiniGameResult.Failure -> {
            Log.w("Lucra SDK", "Failed to start minigame: ${result.failure}")
        }
    }
}
```

- **Usage (tournament mode)**

```kotlin
LucraClient().startMiniGame(
    gameId = "hoops-web",
    gameMode = LucraMiniGameMode.Tournament,
    amount = 5.00,
    matchupId = "tournament-abc-123",
    onProgress = { step ->
        loadingScreen.show(step.displayText)
    },
) { result ->
    when (result) {
        is MiniGameInteractions.StartMiniGameResult.Success -> {
            myWebView.loadUrl(result.session.iframeUrl)
        }
        is MiniGameInteractions.StartMiniGameResult.Failure -> {
            when (val error = result.failure) {
                is UserStateError -> showUserStateError(error)
                is LocationError -> showLocationError(error.message)
                is APIError -> showGenericError(error.message)
                else -> showGenericError("Unable to start session")
            }
        }
    }
}
```

> Prefer the bundled UI? Use [`LucraFlow.MiniGame`](6.3_mini_games_flows.md), it runs the same orchestration and renders the loading screen and WebView for you.

## List the tenant's minigame catalog
### `getMiniGames(onResult)`

Lists every minigame enabled for the current tenant, each with the tenant's subscribed config options (mode, wager amount, group size). Use it to build your own game picker instead of hardcoding game IDs — the `gameId` on each item is the value to pass to `startMiniGame` or `LucraFlow.MiniGame`.

- **Parameters**
  - `onResult`: callback receiving a `MiniGameInteractions.GetMiniGamesResult`.
- **Results**
  - `GetMiniGamesResult.Success` supplies `games: List<MiniGameCatalogItem>`.
  - `GetMiniGamesResult.Failure` wraps an `APIError` (backend or unexpected failure).

### Response Model — `MiniGameCatalogItem`

| Property | Type | Description |
| --- | --- | --- |
| `gameId` | `String` | Identifier to pass to `startMiniGame` / `LucraFlow.MiniGame`. |
| `name` | `String` | Display name of the game. |
| `description` | `String?` | Optional description copy. |
| `imageUrl` | `String?` | Optional artwork URL. |
| `videoUrl` | `String?` | Optional preview video URL. |
| `config` | `List<MiniGameCatalogConfig>` | The (mode, wager amount, group size) options the tenant has subscribed for this game. |

- **Usage**

```kotlin
LucraClient().getMiniGames { result ->
    when (result) {
        is MiniGameInteractions.GetMiniGamesResult.Success -> {
            // Render your own game picker from result.games
            result.games.forEach { game ->
                Log.d("Lucra SDK", "${game.name} (${game.gameId}): ${game.config.size} config option(s)")
            }
        }
        is MiniGameInteractions.GetMiniGamesResult.Failure -> {
            Log.w("Lucra SDK", "Failed to fetch minigames: ${result.failure}")
        }
    }
}
```

## Observe the platform service fee
### `observeGamesMatchupFee()`

Returns a `Flow<Double>` that emits the platform service fee for mini games matchups (e.g. `0.05` = 5%). Defaults to `0.05` until the configuration response is received from the backend. Useful for displaying the winner payout preview on a wager confirmation screen.

```kotlin
LucraClient().observeGamesMatchupFee().collect { fee ->
    val feePercent = (fee * 100).toInt()
    val winnerPayout = wager * 2 * (1 - fee)
    confirmButton.text = "Win up to $$winnerPayout (after $feePercent% fee)"
}
```

## Claim or mark minigame rewards as viewed

Minigame matchup rewards reuse the same `claimReward` / `markRewardViewed` headless methods used for tournament rewards. Fetch rewards with `LucraClient.getUserTournamentRewards(...)`, minigame matchup rewards are returned alongside tournament rewards. See [Headless Functionality — Rewards](1.2.9_headless_interactions.md#lucraclientclaimrewardrewardid-onresult) for the full reference and result types.

```kotlin
LucraClient().claimReward(rewardId = reward.rewardId) { result ->
    when (result) {
        RewardInteractions.ClaimRewardResult.Success -> {
            // Update local UI — the reward is now claimed.
        }
        is RewardInteractions.ClaimRewardResult.Failure -> {
            Log.w("Lucra SDK", "Claim failed: ${result.failure}")
        }
    }
}
```

### Result type reference

| Result Type | Success Payload | Failure Payload |
| --- | --- | --- |
| `MiniGameInteractions.StartMiniGameResult` | `session` (`MiniGameSession`) | `LucraError` (`UserStateError` / `LocationError` / `APIError`) |
| `MiniGameInteractions.GetMiniGamesResult` | `games` (`List<MiniGameCatalogItem>`) | `LucraError` (`APIError`) |
| `RewardInteractions.ClaimRewardResult` | (none) | `RewardInteractions.FailedRewardCall` |
| `RewardInteractions.MarkRewardViewedResult` | (none) | `RewardInteractions.FailedRewardCall` |

Handle each sealed interface exhaustively to ensure you capture both success and error scenarios.


# Setting up Push Notifications
Lucra can setup push notifications for your app to notify users of important events throughout the lifecycle of a Matchup. 

Lucra SDK's push notification works with your existing Firebase push notification solution.

NOTE: Please reach out to Lucra support to start the process of notification setup. This document walks through the steps required after Lucra setup is complete.

```kotlin
class MyFirebaseMessagingService : FirebaseMessagingService() {

    override fun onNewToken(token: String) {
        super.onNewToken(token)
        // This method is called when a new token is generated.
        LucraPushNotificationService.refreshFirebaseToken(token)
    }

    override fun onMessageReceived(message: RemoteMessage) {
        super.onMessageReceived(message)

        // Determines if this push notification is Lucra-specific. We will show the resulting notification if it is
        if (!LucraPushNotificationService.handlePushNotification(
                context = this,
                remoteMessage = message,
                activityClass = MainActivitySdk::class.java,
                smallIcon = R.drawable.lucra_letter_landing
            )
        ) {
            showNotification(message)
        }
    }

    private fun showNotification(message: RemoteMessage) {
        //Show your app specific notifications
    }
}
```

### LucraPushNotificationService.refreshFirebaseToken(token)

Pass in the unique device token that's generated by Firebase.

The Firebase token can also be retrieved from your Activity via...

```kotlin
FirebaseMessaging.getInstance().token
    .addOnCompleteListener { task ->
        if (!task.isSuccessful) {
            return@addOnCompleteListener
        }

        val token = task.result
        LucraPushNotificationService.refreshFirebaseToken(token)
    }
```

### LucraPushNotificationService.handlePushNotification(...)


This function will return `true` if the incoming push notification is Lucra-specific. The Lucra SDK will consume and display the notification to the user.

- **Parameters:**
    - `context`: `Context` Context of the Service
    - `remoteMessage`: `RemoteMessage` The push notification data from Firebase
    - `activityClass`: `Class<*>` The Java class of the Activity that you want the push notification to open after a click.
    - `smallIcon`: `Int` The drawable resource id of the icon you want to display next to the Lucra notification

The function also automatically creates a Lucra-specific default notification channel if one doesn't already exist.
This channel is created with high importance and is used for all Lucra SDK notifications.

## Handling Lucra push notification click events

Within the `activityClass` Activity you specified above, handle the incoming `Intent` and parse the Lucra-specific notification to show a `LucraFlow`. Add `handleNotificationIntent` to the following locations.

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
    super.onCreate(savedInstanceState)
    val flow = LucraPushNotificationService.handleNotificationIntent(intent)
    flow?.let { launchFlow(it) }
}

override fun onNewIntent(intent: Intent) {
    super.onNewIntent(intent)
    val flow = LucraPushNotificationService.handleNotificationIntent(intent)
    flow?.let { launchFlow(it) }
}
```
`onNewIntent` contains the notification data when the Android app is in the background and the notification is clicked.

`onCreate` contains the notification data when the app is dead and the notification is clicked

## Lucra notification payload

A Lucra push carries its display text in the Firebase `notification` block and a `deeplink` entry in
the `data` map. The path of that deeplink is what `handlePushNotification` matches on. A message
with any other deeplink, or none at all, returns `false`.

```json
{
  "notification": { "title": "Matchup accepted", "body": "Your opponent is in" },
  "data": {
    "deeplink": "https://www.lucrasports.com/ContestDetailsGames?gamesMatchupId=<matchupId>"
  }
}
```

| `deeplink` path | Parameters | Notification type | Consumed | Screen the SDK opens |
|---|---|---|---|---|
| `/ContestDetailsSports` | `contestId` | Sports matchup lifecycle | `true` | Sports matchup details |
| `/ContestDetailsGames` | `gamesMatchupId` | Recreational game lifecycle | `true` | Join the recreational game |
| `/Rewards` | `achievementId` | Achievement earned | `true` | Minigames rewards |
| `/referral` | `contestId` or `gamesMatchupId` | Invite | `true` | Sports matchup details, or join the recreational game |
| `/Rewards` | none | Funds and other account notifications | `false` | None |
| `/TournamentDetailView` | `matchupId` | Tournament lifecycle | `false` | None |

The last two rows are not consumed, so they arrive in your own `showNotification` branch and
`handleNotificationIntent` returns `null` for them. Handle those yourself if you want them to open a
screen.

To read the deeplink yourself, check both of these:

- `DeeplinkConstants.NOTIFICATION_DEEPLINK` (`"notificationDeeplink"`), the extra
  `handlePushNotification` sets. `NOTIFICATION_TITLE` and `NOTIFICATION_MESSAGE` hold the text.
- `"deeplink"`, the raw `data` key, which is where Firebase leaves it when it posts the notification
  without calling your service.

## Supplying your own destination

`handleNotificationIntent` has no side effects. It only tells you where the notification wants to
go, which leaves you two options: present the flow it returns, or read the IDs out of the deeplink
and render your own screen. The IDs live in the URL query, not on the returned flow, so route on the
path and its parameters.

Call this from the same `onCreate` and `onNewIntent` hooks shown above. It needs
`androidx.core.net.toUri`.

```kotlin
private const val TOURNAMENT_DETAIL_PATH_SEGMENT = "TournamentDetailView"
private const val REWARDS_PATH_SEGMENT = "Rewards"

private fun handleLucraNotification(intent: Intent) {
    val deeplink = intent.getStringExtra(DeeplinkConstants.NOTIFICATION_DEEPLINK)
        ?: intent.extras?.getString("deeplink")
        ?: return

    val uri = try {
        deeplink.toUri()
    } catch (e: Exception) {
        return
    }

    val gamesMatchupId = uri.getQueryParameter("gamesMatchupId")

    // Other deeplinks also carry a matchupId, so gate on the path segment.
    val tournamentMatchupId = uri.getQueryParameter("matchupId")
        ?.takeIf { uri.lastPathSegment.equals(TOURNAMENT_DETAIL_PATH_SEGMENT, ignoreCase = true) }

    val isRewardsPath = uri.lastPathSegment.equals(REWARDS_PATH_SEGMENT, ignoreCase = true)
    val achievementId = uri.getQueryParameter("achievementId")?.takeIf { it.isNotBlank() }

    when {
        // Your screen, powered by the headless calls below.
        !gamesMatchupId.isNullOrBlank() -> showMyMatchupScreen(gamesMatchupId)
        !tournamentMatchupId.isNullOrBlank() -> showMyTournamentScreen(tournamentMatchupId)
        isRewardsPath && achievementId != null -> launchFlow(LucraFlow.MinigamesRewards)
        isRewardsPath -> launchFlow(LucraFlow.Wallet)
        // Let the SDK route anything you don't recognize.
        else -> LucraPushNotificationService.handleNotificationIntent(intent)
            ?.let { launchFlow(it) }
    }
}
```

### Loading the data for your own screen

With an ID in hand, use the matching headless call:

| Deeplink parameter | Headless call | Reference |
|---|---|---|
| `gamesMatchupId` | `LucraClient().getMatchupDetails(matchupId)` | [GYP Headless Functions](2.3_gyp_headless_functions.md) |
| `matchupId` on `/TournamentDetailView` | `LucraClient().retrieveTournamentDetails(tournamentId)` | [Tournaments Headless](3.3_tournaments_headless.md) |

There is no headless details call for a sports `contestId`. Present
`LucraFlow.MatchupDetails(contestId)` for those, which also accepts a `gamesMatchupId` or a
tournament `matchupId` if you want the SDK's screen for some notifications and your own for others.

A notification tapped from a dead process arrives before the SDK finishes initializing, and headless
calls fail until it does. Gate them with `LucraClient.waitForLucraClient()` and hold the ID rather
than dropping it. See [LucraClient Initialization](1.2.0_initialize_client.md).

Keep `handlePushNotification` in your messaging service and `handleNotificationIntent` in the `else`
branch. The first posts the notification and creates the channel, and the second routes Lucra
notification types added after you write this.

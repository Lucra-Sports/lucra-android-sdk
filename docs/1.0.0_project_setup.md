This SDK (v5.0.0+) requires the following minimum versions in your app environment:

| Component | Minimum Version | Notes |
|------------|----------------|-------|
| **Android Gradle Plugin (AGP)** | 8.10.1 | Requires Gradle 8.12+ |
| **Gradle** | 8.12 | Use Gradle wrapper 8.12+ |
| **Kotlin** | 2.0.21 | Includes new K2 compiler |
| **Compose Compiler Plugin** | 2.0.21 | Managed via `org.jetbrains.kotlin.plugin.compose` |
| **Compose BOM** | 2025.09.01+ | Must match Kotlin version |

### Gradle setup

In your project's `build.gradle` add the following repositories:

```gradle
    repositories {
        google()
        mavenCentral()
        maven { setUrl("https://jitpack.io") }
    }
```

In `app/build.gradle`

```gradle 
// All surface level APIs to interact with Lucra SDK
implementation("com.lucrasports.sdk:sdk-core:{LATEST-VERSION}")
// Optional for UI functionality - transitively includes `sdk-core`
implementation("com.lucrasports.sdk:sdk-ui:{LATEST-VERSION}")

// Required desugaring library, which allows the project to be built with embedded jdks, it's not 
// what is ran on the device (java 11). See more here https://github.com/android/nowinandroid/pull/731

defaultConfig {
  targetSdk = 35 //Target SDK must be 35 or lower
}

compileOptions {
  isCoreLibraryDesugaringEnabled = true
}

dependencies {
  coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.0.4")
}
```

#### Auth0 compliance (if not already using Auth0)

Lucra leverages Auth0 for user auth, if your app doesn't use it already, add the following to your app's default
config.

Gradle.kts

```gradle.kts
android{
    defaultConfig {
        // Dumby placeholders to make Auth0 happy
        addManifestPlaceholders(mapOf("auth0Domain" to "LUCRA_SDK", "auth0Scheme" to "LUCRA_SDK"))
    }
}
```

Groovy

```groovy
manifestPlaceholders = [
        // Dumby placeholders to make Auth0 happy
        'auth0Domain': 'LUCRA_SDK',
        'auth0Scheme': 'LUCRA_SDK'
]
```

### GeoComply Compliance Requirements

> **Important:** The Lucra SDK uses GeoComply for geolocation compliance and fraud detection, which is required for regulated gaming operations. To ensure proper functionality, you must disable conflicting runtime protection mechanisms.

#### Incompatibility with Google Play's Automatic Integrity Protection

Since version 2.17.0, the GeoComply SDK includes runtime protection to enhance security and fraud detection. However, **using it alongside other runtime protection mechanisms, particularly Google Play's Automatic Integrity Protection, may cause conflicts and lead to app crashes**.

When publishing your app on Google Play, you have the option to disable Automatic Integrity Protection. This feature modifies the app in ways that are incompatible with GeoComply's integrity features, which are essential for compliance validation.

**We strongly recommend:**
- Rely solely on GeoComply's integrity protection for compliance needs
- Disable Google Play's Automatic Integrity Protection during the app publishing process
- Disable any other third-party runtime protection mechanisms that may conflict with GeoComply

### Sentry version alignment

> Only applies if your app also uses Sentry.

The Lucra SDK depends on `io.sentry:sentry` for its own internal diagnostics. It never calls
`Sentry.init` and sends nothing to your Sentry project.

All `io.sentry:*` artifacts in an app must resolve to the same version, so **align your Sentry
version with the one Lucra ships — currently 8.54.0 — or newer.** An older version leaves your
Sentry artifacts mismatched against the core Lucra pulls in, which can crash your app at launch with
`Sentry SDK has detected a mix of versions`, or surface as `AbstractMethodError` at runtime.

```kotlin
implementation(platform("io.sentry:sentry-bom:8.54.0"))
implementation("io.sentry:sentry-android")
```

Lucra leverages [Coil](https://coil-kt.github.io/coil/) to render images and SVGs. In your

### Host Activity Requirements

Lucra hosts its flows inside your Activity's `FragmentManager`, and some flows present
system-level UI that **requires a `FragmentActivity`**. In particular, user fund related flows
prompt for device security via Android's `BiometricPrompt`, which can only
be presented from a `FragmentActivity` (or a `Fragment` hosted by one).

**Any Activity that hosts a Lucra flow must extend
[`FragmentActivity`](https://developer.android.com/reference/androidx/fragment/app/FragmentActivity)**
(or a subclass such as
[`AppCompatActivity`](https://developer.android.com/reference/androidx/appcompat/app/AppCompatActivity)).

> **Note:** A pure-Compose app commonly uses `androidx.activity.ComponentActivity`, which is **not**
> a `FragmentActivity`. Hosting Lucra flows from a plain `ComponentActivity` silently fails to
> present the device-security prompt during Add Funds and Withdraw Funds. Switch your host Activity
> to `FragmentActivity` (or `AppCompatActivity`):

```kotlin
// ❌ Cannot present the device-security prompt for Add Funds & Withdraw Funds
class MainActivity : ComponentActivity() { /* ... */ }

// ✅ Correct — FragmentActivity (or AppCompatActivity) can host BiometricPrompt
class MainActivity : FragmentActivity() { /* ... */ }
```

#### Task affinity

**Any Activity that hosts a Lucra flow must use the default application task affinity.** Leave
`android:taskAffinity` unset so it defaults to your `applicationId`. Do not set it to `""` or a
custom value.

```xml
<activity
    android:name=".MainActivity"
    android:exported="true" />
```

If the host Activity already declares `android:taskAffinity`, remove the attribute (or set it to
the same non-empty value as your `applicationId`).

#### Appearance (light/dark) configuration changes

Lucra resolves its color scheme from the host's current configuration. Switching the device between
light and dark appearance is a `uiMode` configuration change, and Android recreates any Activity that
does not declare `uiMode` as self-handled — tearing down and rebuilding the hosted Lucra flow along
with your own Activity state.

**Any Activity that hosts a Lucra flow should declare `uiMode` in `android:configChanges`** so the
flow updates in place instead of being recreated:

```xml
<activity
    android:name=".MainActivity"
    android:configChanges="uiMode"
    android:exported="true" />
```

This matters when Lucra is following the device — `ClientTheme(themeMode = ThemeMode.AUTO)`, or no
`themeMode` with both `lightColorStyle` and `darkColorStyle` supplied (see
[Theming/Appearance](1.2.1_theming.md)). Forcing `ThemeMode.LIGHT` or `ThemeMode.DARK` pins Lucra's
appearance, so a `uiMode` change cannot alter what it renders — though declaring `uiMode` still keeps
your own hosted flow from being recreated.

> **Note:** Declaring `uiMode` makes your Activity responsible for the change. Compose content —
> including Lucra's — picks up the new configuration automatically, but your own inflated `View`s keep
> the attribute values they were inflated with, so night-qualified resources (`res/values-night/`)
> used by your layouts will not refresh until the Activity is recreated. See the "Configuration
> changes" section of
> [Android's dark theme guide](https://developer.android.com/develop/ui/views/theming/darktheme).

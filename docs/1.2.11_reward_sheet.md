# Reward Sheet

The Reward Sheet automatically presents the Lucra "You've won a reward!" bottom sheet
directly over the host app when the SDK initializes, the user is authenticated, and
unclaimed rewards are available.

No manual invocation is required — the sheet appears automatically.

**Requires `:sdk-ui`**

## Prerequisites

- The SDK must be initialized via `LucraClient.initialize(...)` with a `LucraUi` instance
- The user must be authenticated (signed in via Lucra auth)

## Behavior

- On SDK initialization, the sheet auto-shows if the user has unclaimed rewards
- Can be toggled by a feature flag
- Shows once per SDK session (will not re-appear after dismissal)
- If no rewards exist or the user is not authenticated, nothing is shown
- When the user taps "Claim Now", the claim URL opens in the device browser
  and the reward is marked as claimed
- When the user taps "Not Now" or swipes to dismiss, rewards are marked as viewed
  so they will not appear again

## Host activity (FragmentActivity)

Auto-show attaches the reward UI to the **currently resumed** activity using AndroidX
`FragmentManager` (`supportFragmentManager`). Only activities that subclass
[`FragmentActivity`](https://developer.android.com/reference/androidx/fragment/app/FragmentActivity)
(including [`AppCompatActivity`](https://developer.android.com/reference/androidx/appcompat/app/AppCompatActivity))
are tracked and can host the sheet.

- **Plain `Activity` subclasses** are ignored for auto-show: the SDK will not treat them
  as a valid host, so the sheet may not appear until a `FragmentActivity` is in the
  foreground (or may not auto-show at all if the app never shows one).
- **Typical apps** use `AppCompatActivity` for main screens, so this matches common setups.
- **React Native** hosts usually use `ReactActivity`, which extends `AppCompatActivity`,
  so the resumed activity is normally a `FragmentActivity`. If your integration uses a
  different activity type for the foreground UI, ensure it still subclasses `FragmentActivity`
  if you rely on auto-show.
- **Layering:** The sheet is a `DialogFragment` on the host activity’s fragment manager.
  Other overlays (e.g. native or RN modals) may affect stacking order or focus; validate
  in your host app if you use heavy modal UI on top of the main activity.

## Disabling the Reward Sheet

The reward sheet can be globally disabled by passing `allowRewardSheetToDisplay = false` during
[initialization](1.2.0_initialize_client.md). When disabled, the sheet will never appear —
neither inside the SDK UI nor via auto-show — regardless of any other feature flag settings.

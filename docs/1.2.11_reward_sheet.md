# Reward Sheet

The Reward Sheet is a bottom sheet that shows the rewards a user has earned and not yet seen:
tournament prizes, achievement rewards, and promotion rewards such as a first-deposit bonus. The
SDK presents it on its own; no manual invocation is required.

**Requires `:sdk-ui`**

## Prerequisites

- The SDK must be initialized via `LucraClient.initialize(...)` with a `LucraUi` instance
- The user must be authenticated (signed in via Lucra auth)

## When it appears

- **Whenever the signed-in user's account changes**, over your app: on sign-in, so once on launch,
  and when the balance, profile or account status changes, which a deposit, a tournament payout or a
  promotion that pays cash all do. The SDK checks for unseen rewards and presents the sheet about a
  second later over the resumed activity. A promotion that does not pay cash does not move the
  balance, so it appears at the next account change or the next time a Lucra flow opens.
- **When a Lucra flow opens** for a signed-in user, inside the flow. The `MiniGame` flow never
  shows it.

If there are no unseen rewards, or the user is not signed in, nothing is shown. Rewards are marked
seen once they are shown, so the sheet does not repeat them.

## Presenting it yourself

Some events change no account and open no Lucra flow, such as a game ending in a headless
integration, so a reward earned there waits for the next check. To check right away, call:

```kotlin
LucraClient().presentRewardsSheetIfAvailable()
```

It runs the same check as the automatic one: about a second later, over the resumed activity, it
presents the sheet when the user has unseen rewards and does nothing when they have none. It is
safe to call often. Checks run one at a time, and while a reward sheet is already showing the
rewards wait for the next check, so the user never gets two sheets. It does nothing when the
user is not signed in, or when the sheet is [disabled](#disabling-the-reward-sheet).

## What it shows

- Each reward is tagged with what it is, over a second line naming how it was earned: a tournament
  reward reads "Tournament / You placed 1st", an achievement reward carries the achievement's
  description (or its title when it has none), and a promotion reads "Promotion" over the
  promotion's name.
- The sheet is titled "Reward Earned", or "Rewards Earned" when several are shown. A promotion
  reads "Bonus Earned", or "Bonuses Earned" for several; promotions and other rewards are counted
  separately.
- For a tournament or achievement reward, the buttons depend on whether the reward **redeems
  somewhere**, meaning it carries a discount code, a claim URL, or both:
  - A **redeemable** reward shows "Claim Later" and "Claim Now". "Claim Now" marks the reward as
    claimed and opens its claim URL in the device browser when it has one. A reward with a code
    shows a "Copy the code to clipboard" link, which copies the code without displaying it.
  - A physical item shows a single "Continue", which marks the reward as claimed without opening
    anything.
  - A reward that carries nothing at all (no code, no claim URL and no item) shows no buttons,
    only an error message.
- A **promotion** always shows a single "Continue", which opens its claim URL when it has one. A
  promotional cash grant (`PROMOTIONAL_CASH`) shows the amount granted in place of the reward image.
  A grant that has been clawed back is never shown.
- When several rewards are shown, "Claim Now" or "Continue" on one keeps the sheet open on the next,
  and "Claim Later" moves on to the next without claiming. The sheet closes after the last one, or
  when the user swipes it away or taps outside it.
- A reward's `disclaimer`, when the backend supplies one, is shown as fine print below the buttons.
- Rewards passed to `ClaimRewards` and `ClaimAchievementRewards` are deduplicated by `rewardId`, so
  repeating the same reward in the list shows it once.
- Promotion rewards appear only on this sheet: the headless `getUserTournamentRewards` and
  `getUserAchievements` do not return them. If you turn the sheet off and build your own reward UI,
  promotions will not appear in it.

## Host activity (FragmentActivity)

The sheet shown on account changes attaches to the **currently resumed**
activity using AndroidX `FragmentManager` (`supportFragmentManager`). Only activities that subclass
[`FragmentActivity`](https://developer.android.com/reference/androidx/fragment/app/FragmentActivity)
(including [`AppCompatActivity`](https://developer.android.com/reference/androidx/appcompat/app/AppCompatActivity))
are tracked and can host the sheet.

- **Plain `Activity` subclasses** are ignored: the SDK will not treat them as a valid host, so the
  sheet may not appear until a `FragmentActivity` is in the foreground (or not at all if the app
  never shows one).
- **If no `FragmentActivity` is resumed**, the SDK waits for one before fetching, so rewards are not
  consumed while your app is in the background. If a reward sheet is already showing, the check is
  skipped and the rewards wait for the next one. If it found rewards and the activity then goes
  away, the sheet shows on the next resumed `FragmentActivity`.
- **Typical apps** use `AppCompatActivity` for main screens, so this matches common setups.
- **React Native** hosts usually use `ReactActivity`, which extends `AppCompatActivity`, so the
  resumed activity is normally a `FragmentActivity`. If your integration uses a different activity
  type for the foreground UI, ensure it still subclasses `FragmentActivity`.
- **Layering:** The sheet is a `DialogFragment` on the host activity's fragment manager. Other
  overlays (e.g. native or RN modals) may affect stacking order or focus; validate in your host app
  if you use heavy modal UI on top of the main activity.

## Appearance: frosted glass

The sheet renders as a frosted-glass surface, and how the blur is produced depends on what is
behind it.

Auto-show and `getRewardSheetDialogFragment` put the sheet in a window Lucra owns, so it blurs your
app through Android's cross-window blur. That blurs the whole screen behind the sheet, including
the strip above it — but the platform, not Lucra, decides when it is available:

- It requires **Android 12 (API 31) or newer**.
- The system switches it off under battery saver, on low-RAM devices and over some video content,
  and it drops out during the Recents transition.
- When it is unavailable, the sheet falls back to an opaque surface.

### Getting the reliable blur with `GetLucraFlowComposable`

If you embed Lucra UI with `GetLucraFlowComposable`, you can opt into the reliable path instead of
the platform one by telling Lucra what is behind its sheets:

```kotlin
@Composable
fun LucraBackdrop(content: @Composable () -> Unit)
```

```kotlin
LucraClient().LucraBackdrop {
    MyAppContent()
}
```

Wrap once, as high in your Compose tree as is practical. Sheets shown inside that wrapper blur your
content the same way they blur Lucra's own — immediately, on any API level, with none of the
constraints above. Without it, those sheets use the platform blur described above.

This only applies to `GetLucraFlowComposable`, which places Lucra UI inside your composition. The
other entry points render in a window Lucra owns and cannot see into your view hierarchy, so they
use the platform blur regardless.

## Disabling the Reward Sheet

The reward sheet can be globally disabled by passing `allowRewardSheetToDisplay = false` during
[initialization](1.2.0_initialize_client.md). When disabled, the SDK never presents the sheet on
its own — not on account changes, not when a Lucra flow opens, and not from
`presentRewardsSheetIfAvailable()` — regardless of
any other feature flag settings.

Two sheets still appear, because each belongs to something already on screen: the
`ClaimRewards` and `ClaimAchievementRewards` flows when you launch them, and a tournament's
end-of-round sheet, which shows what that tournament paid out plus any achievement rewards the
user has not seen yet.
